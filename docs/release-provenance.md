# Proveniência de release e promoção sem rebuild

Status: `BLOCKED_EXTERNAL`. Esta documentação e os verificadores fecham o contrato local de ligação entre commit, CI, imagens e promoção. Não há manifest remoto do SHA atual, assinatura de autoridade de release, staging autorizado ou promoção executada nesta revisão.

`npm run release:provenance -- --write artifacts/release-provenance.json` só gera um manifesto a partir de checkout Git limpo e exige `GITHUB_SHA`, digest imutável das imagens API/web, SBOM, recibo de resultados CI e commit esperado do DeepSeek. O manifesto inclui SHA fonte/CI, timestamp, caminho/digest do SBOM, caminho/digest do recibo CI, digests de container, versão e digest de migrations, digest da policy, digest do registro de tools e commit esperado do engine. `npm run verify:release-provenance -- --manifest ...` recusa divergência entre SHA auditado, SHA do checkout e `GITHUB_SHA`, reabre SBOM e recibo CI (`--sbom`/`--ci-results` ou referências do manifesto), compara os bytes aos digests declarados, rejeita symlink e bloqueia adulteração ou mudanças em migrations/policy/tools. O workflow publica o SBOM e o recibo CI junto com o manifesto e as imagens OCI.

O workflow CI produz esse manifesto depois de construir e escanear as duas imagens, usando o ID `sha256` observado pelo Docker. A variável de repositório `CVG_DEEPSEEK_EXPECTED_ENGINE_COMMIT` precisa ser configurada com o commit atestado; valor ausente ou `000…000` bloqueia o job. O artifact é evidência de CI para aquele SHA, não aceite de staging nem autorização de produção.

Para promoção, o operador fornece um manifesto explícito de staging com o SHA, artifact digest, caminhos para os arquivos de proveniência e smoke, aprovação humana identificada, autoridade, escopo, aceite de risco e candidate de produção. `npm run verify:promotion-invariant -- --manifest promotion.json` calcula novamente os dois arquivos referenciados dentro de `CVG_PROMOTION_EVIDENCE_ROOT`, rejeita symlinks, exige timestamps ordenados e atuais, e exige que staging e candidate usem o mesmo digest e o mesmo SHA. O campo `approval` também precisa conter uma assinatura Ed25519 sobre a decisão completa; a chave pública confiável deve vir de `CVG_RELEASE_APPROVAL_PUBLIC_KEY`, fora do manifesto. Sem essa autoridade ou com assinatura/digest inválidos, o comando permanece bloqueado. A assinatura comprova a autorização externa, mas não é criada pelo código nem substitui a execução real da decisão humana.

`npm run verify:container-smoke -- --url https://staging.example --release-sha <sha> --artifact-digest <sha256>` mede por HTTPS o health/readiness, headers de segurança e os headers `X-CVG-Release-SHA` e `X-CVG-Release-Artifact-Digest`. Sem identidade, o comando encerra com `CONTAINER_SMOKE_INCOMPLETE` e não considera Compose verificado. O cenário autenticado exige `CVG_CONTAINER_SMOKE_LOGIN`, `CVG_CONTAINER_SMOKE_PASSWORD`, `CVG_CONTAINER_SMOKE_ALLOW_WRITE=true`, nome/telefone de tutor, URLs HTTPS controladas para DeepSeek/provider, `CVG_CONTAINER_SMOKE_PROVIDER_SCENARIO_ALLOW=true`, `CVG_CONTAINER_SMOKE_PROVIDER_SCENARIO_URL`, `CVG_CONTAINER_SMOKE_SHUTDOWN_URL` e um orquestrador explícito de restart. Ele faz login (incluindo MFA), exige cookie `cvg_session` observado com `Secure`, `HttpOnly` e `SameSite=Strict`, executa lookup de pacientes, uma escrita idempotente de tutor, uma transação controlada com receipt/effect/audit/outbox/reconciliation duráveis, exige parada graciosa com outbox preservado, confirma recovery e replay idempotente depois do restart e relê headers de SHA/artifact, health, readiness, DeepSeek e provider. Portanto ele não concede promoção.

O overlay de produção declara os quatro secrets Docker externos (`cvg-deepseek-bearer`, `cvg-deepseek-context`, `cvg-recovery-key` e `cvg-messaging-credential`) e monta suas referências somente em `/run/secrets/cvg`. A verificação estrutural exige os mounts, `CVG_SECRET_DIR` e os nomes externos; nenhum valor secreto é versionado. O CI gera imagens como artefatos OCI e extrai o digest do `index.json`, mantendo a proveniência vinculada ao SHA do checkout.

`npm run verify:production` executa explicitamente o modo estrutural sintético; a invocação direta exige `--structural` ou `--production`. Em produção, `CVG_RELEASE_SHA` e `CVG_RELEASE_ARTIFACT_DIGEST` são obrigatórios e são devolvidos pela API. `npm run verify:production -- --production` falha se eles estiverem ausentes ou malformados, se o commit esperado do DeepSeek for placeholder, ou se os controles preexistentes de TLS, armazenamento, demo, secrets, cookies, backup e runtime não estiverem fechados.
